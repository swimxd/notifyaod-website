Help & feedback.

A few things to check before getting in touch.

Getting started

  1. Set your phone’s native Always-On Display to All day, keeping your preferred style. Disable other AOD automation while testing.
  2. Follow NotifyAOD’s three-step setup: Display access → Notifications → Screen waking. Choose Shizuku (no computer) or guided ADB (Windows, Mac or Linux with a USB cable) for the one-time display permission.
  3. Enable the phone’s “Wake screen for notifications” setting, then confirm in NotifyAOD. You can also skip and try setting-only control. Tests and observations are optional.

Device compatibility

Native AOD behavior depends on your phone and exact OS build. The current app checks an existing OEM setting; it does not support every Android device or create a missing key. If setup cannot detect it, enable native AOD once in phone Settings and return to recheck.

Some phones, including a reported OnePlus 15 running OxygenOS 16, apply AOD changes only after the display wakes. Search phone Settings for “Wake screen for notifications”; on OxygenOS/ColorOS look under Notifications & Quick Settings (or Notifications & status bar) → Lock screen. This may help with arrivals but not with clearing notifications. Menu names vary. NotifyAOD cannot verify this setting automatically.

If that does not help, open Screen waking → Still not working? Other wake methods. Accessibility is the recommended optional fallback because it does not need Shizuku running; it briefly opens the app’s own activity and may flash. Shizuku waking requires its service to remain running and authorized. Native wake lock remains an experimental advanced option. There is no automatic fallback.

OxygenOS / ColorOS permission help

Some builds may require temporarily turning ON Disable system optimization in Developer options before the Shizuku or ADB grant. After permission is granted, turn that switch OFF again. This changes broader system protection, not just NotifyAOD. Recheck access afterward; behavior varies by build.

To enable Developer options, open About device → Version and tap Build number seven times, entering your PIN if asked. Then find Developer options under System & updates or Additional settings. The app links to the supported Developer options page; individual OEM switches may not support direct links.

Status and troubleshooting

Home shows Ready, Setup needed or Paused. Ready means required permissions and connections are available; it does not certify physical AOD behavior. Use Not working? for corrective steps. If you skip wake setup, a later visit offers a dismissible check-in. Fresh installs exclude silent notifications by default; upgrades preserve your choices.

Before uninstalling or changing builds

Use Settings → Help & device test → Disable and restore and confirm the original setting is restored. The older dev.notifyaod beta and com.notifyaod.app release are separate installations. Disable and restore the old one before using the new one.
